# Local Development

Runs the full stack (app + Postgres + Redis + pgAdmin) locally in Docker with
hot reload. Different from production (see [deployment.md](deployment.md)).

## Prerequisites

- Docker + Docker Compose
- [uv](https://docs.astral.sh/uv/) (for editing deps / running Alembic outside Docker)

## Setup

```bash
cp .env.example .env       # then fill real local values
docker compose up -d --build
```

Create the tables:
```bash
docker compose exec app uv run alembic upgrade head
```

Check it's up:
```bash
curl localhost:8000/health          # {"status":"healthy"}
```

- API: http://localhost:8000
- Swagger docs: http://localhost:8000/docs
- pgAdmin: http://localhost:5050

## Local vs. production compose

| | `docker-compose.yml` (local) | `docker-compose.prod.yml` |
|---|---|---|
| App | hot reload, bind mount | no reload, no bind mount |
| Postgres/Redis ports | published to host | internal only |
| pgAdmin | yes (`:5050`) | no |
| nginx / TLS | none | on the host (native) |

## Hot reload vs. rebuild

- **Edit a `.py` file** → uvicorn `--reload` restarts automatically (bind mount).
- **Change a dependency** (`uv add ...`) → rebuild: `docker compose up -d --build`.
- **Edit `.env`** → recreate the container: `docker compose up -d app`
  (a running container won't pick up `.env` changes).

## Migrations (Alembic)

```bash
# after changing a model, generate a migration
docker compose exec app uv run alembic revision --autogenerate -m "what changed"
# review the generated file in alembic/versions/ (adjust if needed), then apply
docker compose exec app uv run alembic upgrade head
```

> Autogenerated migrations are drafts. Adding a `NOT NULL` column to a populated
> table needs a `server_default` for the backfill, or the migration fails.

## Running module self-checks

Several core modules have a `demo()` self-check:
```bash
docker compose exec app uv run python -m app.core.security
docker compose exec app uv run python -m app.core.totp
```
